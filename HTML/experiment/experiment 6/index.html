    Interview Q&A: Functions, Closures, IIFE

    Short answers followed by concise examples.

    1) What is a closure?

    A closure is a function plus the lexical environment in which it was defined — it "remembers" variables from the outer scope even when executed elsewhere.

    // closure example
function makeCounter(){
  let count = 0;
  return function(){
    count += 1;
    return count;
  }
}
const c = makeCounter();
console.log(c()); // 1
console.log(c()); // 2

    2) Classic loop + closure pitfall

    Using var in a loop binds the same variable; fix with let or an IIFE.

    // bug (var)
for(var i=0;i<3;i++){
  setTimeout(()=>console.log(i),100); // prints 3,3,3
}

// fix with let
for(let i=0;i<3;i++){
  setTimeout(()=>console.log(i),100); // 0,1,2
}

// or fix with IIFE
for(var i=0;i<3;i++){
  (function(v){ setTimeout(()=>console.log(v),100); })(i);
}

    3) What is an IIFE and why use it?

    Immediately Invoked Function Expression — runs immediately and creates a private scope (useful before modules and let were common).

    (function(){
  const secret = 42;
  console.log('IIFE runs once with secret', secret);
})();

    4) Function vs Arrow function differences

    Arrow functions have lexical this, cannot be used as constructors, and don't have arguments. Use regular functions when you need a dynamic this or to use new.

    5) Practical closure interview task — module pattern

    const Counter = (function(){
  let n = 0;
  return {
    inc(){ n++; return n; },
    dec(){ n--; return n; }
  };
})();
console.log(Counter.inc()); // 1
